# Nocturne — The Next 10 Development Sessions (Document D)

**Status:** a proposal, dated 25 October 2026. It pairs with:

- [Document A](./NOCTURNE_R3_INTEGRATION_REVIEW.md), the integration review;
- [Document B](./NOCTURNE_INTEGRATED_MASTER_PLAN.md), the master plan;
- [Document C](./NOCTURNE_ROADMAP_PROPOSAL.md), the roadmap and tasks.

**What a session is.** One focused block of about 2–3 hours. Sessions are ordered by dependency, not by date: run them whenever your week allows.

**What the sessions produce.** Every session except 9 produces working, tested changes. Session 9 is a design note the schema depends on.

**Before you start:**

- Keep **one platform task in progress at a time.** Task 167 is in progress now, so it finishes first (session 1).
- Sessions that touch a real client project or account say so. **None of them runs before you approve it.**

---

## How every session starts and ends

**Starting (about 10 minutes)**

1. Read the task's resume note (in the build plan's notes).
2. `git status`, then `git pull` on `main`, then switch to or create the task branch.
3. `npm run check`. If it's red, fix that first.

**Ending (about 10 minutes):** write a resume note in the task's notes, in this format:

```
Session <n> · <date> · task <id>
Done: <what works now, with the commit or PR>
Next: <the first concrete step next time>
Traps: <anything surprising, such as a flaky test or a workaround>
Checks: npm run check <pass|fail>; e2e <ran X specs|not run>
```

**Ending rules**

- Never stop mid-migration or with `main` red.
- If a session runs out mid-task, commit to the branch with a "WIP" message, so the next session starts from a known state.
